# Next delivery stages

Six independent libraries now compose the product: core, storage, runtime,
providers, workflows and UI. Production queue migration is outside this work.
The earlier endurance run stopped at the operator's request after 9h47; it must
not be restarted or labelled a 24-hour pass.

1. Browser qualification: editing, human answers, profiles, keyboard/mobile layouts,
   pause and restart. HTTP lifecycle tests already execute real child processes.
2. Bounded real feature: compare approved-scope and deep-planning templates on
   equivalent tasks; measure tokens per accepted change, missed defects and human
   interventions. Subscription savings are not inferred from token shares.
3. OS qualification: actual Linux/macOS process-tree/restart tests; Windows real
   restricted-token ACL and disk-full fixtures. Static checks are not OS execution.
4. Operational hosting: qualify server supervision, provider subscription-reset
   payloads, retention and backup/restore. New endurance runs need a separate budget.
5. Visual authoring: graph diff, drag-and-drop layout independent of semantic
   digests, explicit portfolio admission and reusable bugfix/research templates.
6. Application integration: approved task artifacts through an adapter. Production
   import requires backup, one owner, evidence reconciliation, pilot and rollback.
   Historical completion never grants fresh acceptance.

Optional terminal hosting, remote executors and external trackers remain separate
extensions. Core and ordinary pipes execution do not require Node.js or tmux.
The running engine does not rewrite itself while owning a queue.
